1. What is Sharko?

Sharko is a small program you run in the terminal. It answers one question about a loan application:

The question Sharko answersIf this loan application would be rejected, what is the smallest change to the loan amount or the loan term that would get it approved?

To answer it, Sharko learns from a public dataset of 4,269 past loan decisions (the Loan Approval Prediction Dataset from Kaggle, in an Indian lending setting). From those decisions it builds a model: a formula that gives any application a chance of approval from 0% to 100%. A chance of 50% or more counts as approved. All amounts are in Indian Rupees (INR).

A worked example

Here is a real run of the built-in example application:

EducationGraduateAnnual income4,100,000 INR

Assets (home, business, luxury, bank)2,700,000 / 2,200,000 / 8,800,000 / 3,300,000Loan term asked for8 years

Change the loan term onlyNothing found. Sharko tried all 9 other terms.
Change both amount and termFound. 14,600,000 INR over 4 years gives a 54.1% chance (approved).

What Sharko is not

  • Not a lender. The result is a model-generated what-if, never a loan offer or a decision.
  • Not financial advice. A change that works for the model is a pattern in past data, not a recommendation.
  • Not a guarantee. A high chance of approval is the model's estimate. It is not a promise that a real lender would approve.
  • Not a form filer. Sharko never submits anything. It only reads, scores and reports.
Why can a bigger loan become approved?The model only follows patterns in the past loans it studied. A bigger loan can score higher because of those patterns, not because bigger loans are safer. Sharko says this in the result whenever the suggested amount is larger than the one asked for.

2. How Sharko works

Sharko works in four steps. Steps 1 and 2 always happen. Steps 3 and 4 happen only when the first answer is "not approved".

1 LearnThe model studies 4,269 past loan decisions. Run once.
2 CheckYou enter one application. The model gives a chance of approval. Every time you check.
3 SearchTry other amounts and terms, closest to yours first.
4 CompareThree ways side by side, with the closest marked.
Steps 3 and 4 run only when the chance of approval is below 50%.

1. Learn. The train command shows the model the past loans. Sharko tries three kinds of model (logistic regression, random forest, gradient boosting), tests each with a repeated practice test, and keeps the best one. In this project the winner is gradient boosting. You do this once.

2. Check. You answer 11 short questions about one application. The model returns a chance of approval. At 50% or more the answer is approved, the search is skipped, and you get a report showing how safe the approval is.

3. Search. If the chance is below 50%, Sharko tries other loan amounts and terms, nearest to your request first. It scores each option with the same model and stops at the first one that reaches 50%.

4. Compare. Sharko runs the search three ways and shows them side by side. The way with the smallest change is marked as the closest.

What stays fixed and what can change

Never changes during a search (fixed)Can change during a search
Education, self-employed, number of dependents, annual income, CIBIL score, and the four asset values (residential, commercial, luxury, bank)Loan amount and loan term only

The three ways of searching

WayWhat changesHow many options it can try (real data)
Amount onlyThe loan amount. The term stays as submitted.392: every amount from 300,000 to 39,500,000 in steps of 100,000, except yours
Term onlyThe loan term. The amount stays as submitted.9: the terms 2, 4, 6 ... 20 years, except yours
Amount and termBoth. Each option must differ from yours in both.Up to 3,528 (392 amounts x 9 terms)

How Sharko decides what is "closest"

Every option gets a distance from your request. A distance of 0 means no change; bigger means a bigger change. Sharko tries options from the smallest distance up, so the first approved option is also the smallest change.

distance|new amount - old amount| / (largest amount - smallest amount) + |new term - old term| / (longest term - shortest term)

Worked example, from the run in section 1 (old: 12,200,000 over 8 years, new: 14,600,000 over 4 years):

PartCalculationResult
Amount part2,400,000 / (39,500,000 - 300,000) = 2,400,000 / 39,200,0000.0612
Term part4 years / (20 - 2) = 4 / 180.2222
Distance0.0612 + 0.22220.2834
Ties and orderIf two options have the same distance, Sharko tries the smaller amount first, then the shorter term. Ties are decided on exact whole numbers, never on rounded decimals, so the same input always gives the same answer.

3. Quick start

Run every command from the Sharko project folder. You need Python 3.10 or newer.

0. Install (once)

python -m pip install -r requirements.txt

This installs scikit-learn, pandas, numpy, matplotlib, joblib and pytest.

python -m sharko

2. Teach Sharko (once)

python -m sharko train

Sharko learns from loan_approval_dataset.csv and saves the model to artifacts/model.joblib. Run it again only if the data changes.

3. Try the built-in example

python -m sharko check --example

No typing needed. Sharko checks a sample application, prints the result, and saves a report in the Reports folder.

4. Check your own application

python -m sharko check

Sharko asks for your first and last name (they only name your report file), then 11 short questions. Press Ctrl+C at any time to quit.

python -m sharko experiment
python -m sharko report --open

Run experiment first. It tests many loans and takes a short while. Then report draws four charts and opens them in your browser.

6. Check how steady and reliable the results are (optional)

python -m sharko scenarios
python -m sharko robustness
python -m sharko evaluate

These are for analysts. Section 7 explains what each one shows.

Something went wrong?The most common messages and their fixes are in section 11, Troubleshooting.

5. Your report file

Every check saves an HTML report by itself, so there is nothing extra to run. It is one file with everything inside, so you can open it in any browser or send it to a teammate.

Where it is saved and what it is called

  • Folder: Reports, inside the Sharko folder. The terminal prints the full path.
  • File name: FirstName_LastName_Results.html, for example Ana_Cruz_Results.html.
  • Spaces become underscores. Accents and symbols are removed, so a name like José becomes Jose.
  • Running check again with the same name saves ..._Results_2.html, then _3, so nothing is overwritten.
  • Open it by double-clicking the file, answer y when Sharko asks, or add --open.

7. How steady and how reliable are the results?

A model can look good once and still be fragile. Three analyst commands test that. Every number below comes from a real run on the full dataset, and the numbers are the same each time because the whole pipeline uses a fixed seed (42).

Negative assets and different random splits

The dataset has 28 loans with a negative residential asset value, which is not possible for a real asset. python -m sharko robustness asks two questions:

  • Do those 28 loans matter? It trains, tests and runs all three searches twice: once on every loan, and once without those 28.
  • Does the result depend on one lucky split? It repeats the whole run with 5 different random splits (seeds 42 to 46). Use --seeds 10 for more.

Do the percentages mean what they say?

A model can rank loans well and still give percentages that are too high or too low. python -m sharko evaluate checks this. It prints the Brier score (the average squared gap between the model's chance and what happened; 0 is perfect, and always answering 50% scores 0.25) and groups the 854 test loans by the chance the model gave them:

Chance givenLoansModel saidTruly approved
0% to 10%2920.4%0.0%
10% to 20%1013.8%0.0%
20% to 30%425.2%25.0%
30% to 40%734.8%14.3%
40% to 50%346.1%66.7%
50% to 60%253.6%50.0%
60% to 70%665.2%100.0%
70% to 80%1376.1%76.9%
80% to 90%985.0%44.4%
90% to 100%50899.5%99.6%
What this meansThe Brier score is 0.0144 and the average gap is 1.3 percentage points, so the percentages are reliable at the ends: loans scored under 10% or over 90% were almost always rejected or approved as predicted. The middle is thin. Only 54 of the 854 test loans scored between 10% and 90%, and the 80% to 90% group was truly approved less than half the time (9 loans). Sharko stops at the first option with 50% or more, so a suggested change usually lands in that middle zone. Read a suggested "52% chance" as a weaker signal than a "99% chance". Small groups are noisy, so do not read much into any one row.

Tests

Run all tests with python -m pytest. There are 215, and they take 2 to 3 minutes. The project is built test first: a failing test is written, then the code that makes it pass. Tests run inside a scratch folder, so they never leave files in your project.

House rules for the code

  • Run everything as python -m ..., with no shell-specific syntax.
  • Use pathlib for paths and pass encoding="utf-8" to every text file.
  • Anything printed in the terminal is plain ASCII, so it looks the same on every system.
  • Terminal output stays within 72 columns so it never wraps badly.

10. Rules the code never breaks

These rules come from the project paper. They keep the results fair, repeatable and honest.

  • Only the loan amount and loan term change during a search. Every other field stays as submitted.
  • The split is 80/20, stratified on the loan status, with seed 42. The search limits, the scaling and the choice of model use the 80% training part only. (robustness tries other seeds only to test how steady the results are. The official run stays on seed 42.)
  • Approved means a model probability of 0.5 or more. The same model and threshold are used for every option.
  • Options are tried in order of distance, then amount, then term. Ties are decided on exact whole numbers, never on decimals.
  • No single "best" way is declared. Sharko shows the three ways side by side and marks the closest; it never combines them into one weighted score.
  • Every result carries the disclaimer and shows the original and new amount and term, the model score and the distance.
  • History is write-only. Nothing ever reads it back to change a search or the model.
  • Sharko never submits anything and never changes the applicant's own details.

12. Ethics and limits

Read this before using any resultModel-generated what-if result. This is not a lender decision, a loan offer, or financial advice. A high chance of approval is an estimate, not a guarantee that a real lender would approve. The model reflects patterns in a public dataset that lacks economic variables (such as inflation and interest rates) and demographic detail. If no approved option is found, that means none was found within the searched amounts and terms, not that none exists. Scores can change with a different data split.
  • The results describe how this trained model behaves. A different model or a real lender could answer differently.
  • Sharko does not know if an applicant would accept a changed loan. A suggestion is never an offer.
  • The dataset has 28 loans with a negative residential asset value. They are kept as they are. The robustness check (section 7) shows that removing them changes accuracy by 0.0001 and each flip rate by about 2 points at most.
  • The results are steady across five random splits, but they come from one dataset. They should not be generalized automatically to other lenders or populations.
  • The percentages are most reliable near 0% and 100% and least reliable in the middle, which is where a suggested change usually lands (section 7).
  • Because the dataset has little demographic detail, Sharko makes no claim that the model is fair across groups.
  • Historical lending patterns can carry their own biases, and the model learns them.

Glossary

WordPlain meaning
Chance of approvalThe model's estimate from 0% to 100% (also called the approval score, 0 to 1). 50% or more counts as approved.
Way (strategy)One of the three searches: amount only, term only, or both.
FlipA rejected application that becomes approved after a change. The "flip rate" is how often a way finds one.
Option, try, configurationOne amount-and-term pair the search scores. "Options tried" and "configurations evaluated" mean the same thing.
Distance (normalized distance)How far an option is from your request. 0 means no change.
Eligible loanA held-back test loan that the data marks Rejected and the model also rejects.
Held-out (test) data20% of the loans, kept aside and never used for learning, so the scores are honest.
Cross-validation (CV AUC)A repeated practice test on the training loans, used to choose the best model.

Brier scoreThe average squared gap between the model's chance and what happened. 0 is perfect; always answering 50% scores 0.25.
CalibrationWhether a "70% chance" is truly approved about 70% of the time.
Seed / splitA number that fixes how the loans are shuffled into the 80% and 20% parts. A different seed gives a different split.
